# Discord Bot開発チケット（Stackchan Team運営効率化）

## 全体設計（着手前に二人で合意しておくこと）

- [ ]  **DBスキーマの共有**：進捗管理とタスク割り当ては同じテーブル構成を使えそうなので、着手前にざっくり設計をすり合わせる（担当者、対象マイルストーン、ステータス、期限）
- [ ]  **Discord Embed(埋め込みメッセージ)フォーマットの統一**：通知系・管理系どちらも同じ見た目で投稿されるように、色・レイアウトのルールを最初に決める
- [ ]  **botのコマンド体系（プレフィックス、命名規則）を統一**

---

## 担当A: 通知パイプライン系（Kura）

### A-1: GitHub CI/デプロイ通知

- **概要**：中継サーバー(FastAPI)・アプリのGitHub Actionsのビルド結果、Push/PRをDiscordに流す
- **スコープ**
    - [ ]  GitHub Webhook or Actions側からのAPI呼び出しを受けてDiscordに投稿
    - [ ]  Push / PR作成 / PRマージ / ビルド成功・失敗、それぞれ別チャンネル or 別Embed色で区別
- **完了条件**：実際にPushしたら数秒以内にDiscordに通知が飛ぶ
- **技術メモ**：sec-watchのGitHub Actions→Slack通知の構成をDiscord向けに移植すればOK

### A-2: セキュリティドキュメント更新通知

- **概要**：STRIDE分析表や6.3の受容リスク等のドキュメントが更新されたらDiscordに通知
- **スコープ**
    - [ ]  対象ドキュメント（リポジトリ内のmd等）の変更をGit差分から検知
    - [ ]  更新内容の要約（差分の見出しレベルでOK）をEmbedで投稿
- **完了条件**：ドキュメントを更新してpushすると、変更箇所の概要がDiscordに流れる

---

## 担当B: 状態管理系（たくみ）

### B-1: マイルストーン進捗チェックリスト管理

- **概要**：F-1〜F-3、マイルストーン(疎通→音声→統合)ごとに進捗をDiscordから宣言・確認できるようにする
- **スコープ**
    - [ ]  マイルストーン・機能ごとのステータスをDB管理（未着手/進行中/完了）
    - [ ]  Discordコマンドでステータス更新（例: `/progress F-1 音声対話 done`）
    - [ ]  現在の全体進捗を一覧表示するコマンド（例: `/status`）
- **完了条件**：誰かが `/status` を打つと、7人分の担当領域の進捗が一目でわかる

### B-2: タスク割り当て・リマインド

- **概要**：要件定義書「7. 未決事項」等のタスクを担当者に割り当て、期限が近づいたらリマインド
- **スコープ**
    - [ ]  タスク登録（担当者、内容、期限）
    - [ ]  定期実行（APScheduler等）で期限前にリマインドDM or チャンネル投稿
    - [ ]  タスク一覧・自分の担当タスク確認コマンド
- **完了条件**：登録したタスクの期限前に、担当者に自動でリマインドが飛ぶ

## 補足

- 両方とも `discord.py` + 非同期処理（asyncio）が前提
- B側はDB（SQLite想定、拡張が必要ならPostgreSQL）が必要になるので、最初にスキーマ設計を軽くすり合わせてから着手すると手戻りが少ない
- 完成した機能から順次チームのDiscordに投入していく想定（一括リリースではなく段階的でOK）

## Embedフォーマット統一ルール

**色は用途で固定**

| 用途 | 色 | HEX |
|---|---|---|
| 完了 / CI成功 | 緑 | `0x2ECC71` |
| 進行中 | 黄 | `0xF1C40F` |
| 未着手 / 中立 | グレー | `0x95A5A6` |
| 失敗 / CI失敗 | 赤 | `0xE74C3C` |
| 一般通知（ドキュメント更新等） | 青 | `0x3498DB` |

**レイアウトルール**
- `title` は絵文字1つ＋日本語（例: `📊 進捗状況: F-1 音声対話`、`✅ Build Success: relay-server`）
- `description` に1行サマリ、詳細は `fields` に構造化して入れる（本文に長文を詰め込まない）
- `timestamp` は必ず入れる（`datetime.utcnow()`）
- `footer` に発信元を書く（`GitHub Actions` / `最終更新: ユーザー名` など）

**実装ルール**
- 全機能、共通の `build_embed(title, description, kind, fields, footer)` 関数を必ず経由する
- 個別実装側で `discord.Embed()` を直接呼ばない

## コマンド体系統一ルール

- **形式**：Discordスラッシュコマンド（`/`）で統一。テキストコマンド（`!task`等）は使わない
- **命名**：`/<対象名詞> <動詞>` の順、両方英語、省略しない
  - 例：`/task add`, `/task list`, `/task done`, `/progress show`, `/progress update`
- **対象名詞は固定語彙**：`task`（個別タスク）/ `progress`（マイルストーン進捗）の2つのみ。増やさない
- **動詞は固定語彙**：`add` / `list` / `update` / `done` / `show` の5つの範囲で収める。新機能追加時もこの語彙で表現できないか先に検討する
- **引数はDiscordのスラッシュコマンドUI（オプション引数）で受ける**、自由記述のパースはしない（`/task add title:"" milestone:F-1 assignee:@user due:2026-08-20` のような形）
